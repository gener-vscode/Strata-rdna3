# Speed A/B: chunk 8192 against chunk 32768 (fork, IQ3_XXS, one 7900 XT)

Both arms are the **same engine binary** `fb975936515c` in this tree, the same model, the same pack, the same args, the same `--expert-cache auto` result (8468 slots / 13.70 GiB in both), and one changed line in `rdna3/configs/iq3_xxs-1gpu.json`:

| arm | `STRATA_PREFILL_AUTO_MAX` | engine start | prompt chunk the engine picked |
|---|---|---|---|
| 1 | 32768 | 22:13:23 | 32768 tokens, 192-slot ring (`logs/rdna3-iq3_xxs.log:58,60`) |
| 2 | 8192 | 22:29:56 | 8192 tokens, 192-slot ring (`logs/rdna3-iq3_xxs.log:216,218`) |

This is the clean isolation the memory question needed: only the chunk moved, and everything memory-related followed it.

Arm 1's 1.9–2.05k numbers are all runs with 75085 tokens already reused, so they are not the chunk's doing and cannot be lined up against arm 2's runs 1-to-1.

**No matched 32768 numbers exist yet for the 4K/16K/32K bench prompts.** Until one run of the same bench on arm 1 exists, the honest statement is: 7.1 GiB of RAM came back, and the matched speed difference is unmeasured.

## 4. To finish the speed half

```sh
# 1. rdna3/configs/iq3_xxs-1gpu.json -> "STRATA_PREFILL_AUTO_MAX": "32768"   (restart the way you did before)
# 2. same bench, same prompts, same server:
.venv/bin/python tools/strata_bench.py --url http://127.0.0.1:8080 --long --runs 3 \
      --out bench/ab-memory/speed-32768
# 3. put them side by side:
.venv/bin/python tools/strata_bench.py --compare-only bench/ab-memory/speed-32768 \
      --compare bench/ab-memory/speed-8192
```

Read three lines from that compare: 4K prompt tok/s, 16K prompt tok/s, 32K prompt tok/s. Those are the only numbers that say whether the 32768 chunk was earning its 7 GiB. Note that arm 1 needs `--long` too, otherwise 32768-token chunks are never used and the test proves nothing.

## 5. Still open, unchanged by this arm

- Both arms end with 414 MiB of VRAM free and the engine's #2065 warning. The upstream engine ended at 714 MiB because its cache reserve adds `+256 MiB for what is allocated after the cache` and ours does not. That is the remaining real fork-vs-upstream code difference, and it needs its own test (`--vram-reserve-mib 640` or `1024`, then compare slots and tok/s).
- `STRATA_PREFILL_RING` stayed 192 in both arms; upstream ran 96. Whether the ring is worth anything on this card is a separate measurement.
- The 8192 arm's decode spread is wide (52–79 tok/s chat, 55–110 agent), wider than the prompt numbers; a single run is not enough to compare decode speed at all.

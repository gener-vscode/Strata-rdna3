## 1. Original question, answered

Fork RSS 38.47 GiB vs upstream 32.47 GiB. NOT caused by `STRATA_RESIDENT_PIN` (user proved: setting 0 in the fork left RSS unchanged) and NOT caused by `--resident-budget-gib` (identical 37 in both). Cause = **`STRATA_PREFILL_AUTO_MAX` lets `--prefill auto` reach 32768-token chunks, which inflates the prompt path's lend region, and in resident mode the lend region's experts are duplicated into RAM.**

The identity, verified on two models:
```
resident complement = experts the GPU cache does not hold + lend-region experts kept in RAM
                    = fixed by the model                   + f(chunk)   <- the only controllable term
```
Mechanism chain (all from this tree's code):
1. Chunk buffers are linear in chunk — `Prefill::bytes_needed_impl` (`src/prefill/prefill.cpp:2717-2746`), every term `T × model_dim` (residual, router logits `T*LR`, step counts).
2. Those buffers are **borrowed from the expert cache's top slots**, not freshly allocated (`generate.cpp:736-738`, `lend_slots` at `generate.cpp:8001-8003`), capped at `kAutoLendPct` = 90% of cache when copies DMA from pinned RAM else 85% (`generate.cpp:8038-8045`).
3. In resident RAM mode the RAM copy must ALSO hold the lent slots' experts (`src/core/expert_source.cpp` fork 3566-3599 / upstream 3632-3665; `generate.cpp:451` "out in the lend region is held in RAM already"; upstream comment `generate.cpp:9775-9782` #2090). Reason: chunk ≥ `stream_all_min`(1024) streams **every** non-held expert; lent slots are busy as buffers, so their experts must come from the RAM side.
4. Both trees have a RAM guard that steps the chunk down (32768→16384→8192) when free RAM cannot cover the extra loan + 6 GiB (fork `generate.cpp:8072-8098`, upstream `9775-9805`).

Upstream stays at 8192 on gfx1100 by itself (bare `--prefill auto` is only auto-lifted for RDNA4: `prefill_auto_bare` + `gfx_arch_is_gfx12`, upstream `generate.cpp:3890-3935`).

## 3. Key secondary findings

- **Chunk saturates past ~20K.** `AUTO_MAX=32768` runs settled at **23296 / 23040 / 22784** tokens (RAM guard), loan 6397–6532 slots (10.26–10.48 GiB) regardless, and printed `lend region: 6252 of its 6532 slots keep their experts in RAM too` + `WARNING ... only 6252 of their experts fit in RAM: the others are read from the files` — i.e. 280 slots (~0.44 GiB) OVER the 37 GiB budget. One such run logged a 60 s stall (`logs/rdna3-iq2_xs.log:1051-1052`, engine stopped itself). `journalctl -u strata` records `43.5G memory peak, 5.5G memory swap peak`.
- Chunk-count = the cost driver (each ≥stream_all_min chunk streams every non-held expert once): 88K prompt: 6 chunks @16384 vs 4 @24576; 124K: 8 vs 6; 142K: 9 vs 6. User's real traffic from logs: 88,422 / 92,206 / 108,211 / 124,241 tokens; this conversation is 142K+. So big chunks DO pay here (I earlier wrongly said "only if ≥40K" — corrected in CHUNK-20K-24K.md §4, split into "(a) does it help: yes" vs "(b) can the box pay: barely").
- `--no-prefill-borrow` is a net loss (+1.43 GiB RAM, cache halved, hit rate 48.9%, real disk reads: `file tier I/O ... OS read 50325.4 MB for 6590.3 MB of expert reads`). Reason: resident rule means VRAM pressure becomes RAM pressure either way; a permanent session-long reserve is worse than a loan.
- `--vram-reserve-mib` is the only free VRAM knob. Fork reserves `512 MiB (+105 MiB draft head)`; upstream reserves `512 (+184 draft head, +256 for what is allocated after the cache)` — that missing "+256" is the remaining genuine fork-vs-upstream code difference (fork ends at 414 MiB free and prints the #2065 warning; upstream ends at 714 MiB, no warning). Engine itself now asks for `--vram-reserve-mib 832` at 224K context.
- `--pool-workers`: warning from `src/kernels/cpu/pool.cpp:1009`; default 0 = "all physical cores minus the host's" (`generate.cpp:614`) = **7** on this box; writing 8 oversubscribes. Only affects decode (prefill pool sharing is off). UNMEASURED.
- `STRATA_PREFILL_CPU_SHARE=0` is not suppressing anything: default is off on HIP, `g_share_default = false` (`prefill.cpp:240-254`); `STRATA_PREFILL_CPU_SHARE_MAX=4096` is dead config while off. Upstream CUDA-only gains: Q4_K_XL −13%, Q2_0 −7%, **IQ2_XS −3.4%**, IQ2_XS@250tok −8.5%. Also changes output bytes (mean KL ~0.004). Low value.
- `STRATA_HIPBLASLT_TUNING` points at `gfx1100-hipblaslt-100200.txt` but runtime is 100202 → table refused, hipBLASEx used. Upstream has `gfx1100-hipblaslt-100202.txt`.
- Conversation cache parked 1.69 GiB (`parked=1 bytes=1819200856`, 109761 tokens/731.9 ms) at 2048 MiB; at 1536 it parked 1.47 GiB and REFUSED four more attempts (snapshot 1560/1593/1769/1812 MiB exceeds budget).
- Parallel tool calls in one response are dispatched together but **executed serially** (~2 s apart) — do not read inter-command timestamp gaps as system behaviour.
